01 / CONVERSATION

Talk by command.
Or use a name.

Use /worldspeaker ask. Or address the configured character by name in normal chat. Set up to eight aliases.

A small phrase.
A useful next step.

After an answer, use five supported follow-up phrases, such as “why?” and “tell me more.” The window lasts up to 30 seconds.

Your server.
Your access rules.

Grant conversation access to selected players. Set the public name, aliases, chat style, and request time limits.

Start with three commands.

Find the character name and command help. Send a question. Close local follow-up recognition when you finish.

/worldspeaker end does not erase agent memory or cancel work already accepted.

COMMAND EXAMPLE — NOT A LIVE CAPTURE

/worldspeaker help /worldspeaker ask What can you help me with? /worldspeaker end

A clear boundary at each step

02 / CONNECTION & CONTROL

Built for the server.
Linked to OpenClaw.

The server mod handles player input and reply delivery. The companion connects requests to an OpenClaw agent.

Clear reply targeting

Character replies target the requesting player’s current connection, not the whole server.

Bounded work

Time limits and repeat controls bound local work. Late answers lose local delivery eligibility.

Clean chat

Diagnostic details use separate logging paths. Players get character text or a short service notice.

Explicit access

The administrator grants conversation access. Operator status alone does not grant it.

Evidence boundary: These controls have implementation and offline test evidence. Live behavior, reply timing, and host isolation are not yet verified. Local cancellation does not prove that provider work stopped.

Targeted replies are not confidential conversations.

Character context is shared. Do not send confidential information. The ask command keeps its input out of public chat, but not out of shared character context. Natural chat remains public. Actual OpenClaw workspace and admin-memory isolation still need verification before deployment.
